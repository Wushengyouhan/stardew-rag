## 2. 输入与输出

### 2.1 输入 `PageSource`

| 字段 | 来源 | 用途 |
|---|---|---|
| `pageid` | API | 稳定页标识 |
| `title` | API | 标题与 URL |
| `revid` | API | 差量同步 |
| `extract` | `prop=extracts&explaintext=1` | 按 `==` / `===` 切正文 |
| `parseHtml` | `action=parse` 的 infobox 区域 HTML | 可选；NPC 等页的 `__infobox__` |

### 2.2 输出 `Chunk`

与 `01` §6.3 一致：

| 字段 | 规则 |
|---|---|
| `id` | `{pageid}#{order}` |
| `section` | 章节名；infobox 为 `__infobox__`；导语为 `__lead__` |
| `text` | 清洗后的纯文本 |
| `url` | `https://zh.stardewvalleywiki.com/{title}` |
| `order` | 页内从 0 递增 |

入口函数：`chunkPage(source: PageSource): Chunk[]`。

---

## 3. 切片规则

1. **Infobox**：若提供 `parseHtml`，用 cheerio 解析 `#infoboxtable`，去掉 `<style>`，行格式为 `标签：内容`。
2. **导语**：第一个 `==` 标题之前的 extract 正文 → `__lead__`（非空才输出）。
3. **H2 / H3**：MediaWiki 行首 `== 标题 ==`、`=== 标题 ===` 各成一块；块内正文到下一同级或更高级标题为止。
4. **H4 及以下**：不单独成块，正文追加到当前 H3 块末尾。
5. **空块**：`text` 清洗后为空则跳过（例如仅含 tab 的「画廊」占位）。
6. **清洗**：行 trim；去掉纯空白/tab 行；infobox 文本去掉 `.mw-parser-output` 样式泄漏。

## 5. 测试数据

```text
tests/fixtures/wiki/           # API 原文（json）
  abigail.json                 # NPC，含 parseHtml
  parsnip.json                 # 作物
```

脚本：

| 命令 | 作用 |
|---|---|
| `npm run fetch:fixtures` | 从维基重新拉取 `tests/fixtures/wiki/*.json` |
| `npm run fixtures:chunks` | 根据 wiki 重新生成 `tests/fixtures/chunks/*.jsonl` |
| `npm test` | 含「与黄金 jsonl 一致」用例 |

修改 `lib/chunk.ts` 后：先 `npm run fixtures:chunks` 更新黄金文件（确认 diff），再 `npm test`。

## 6. 与正式知识库的关系

阶段 B 的 jsonl 仅用于测试，提交在 git 中。

全站同步时，同一套 `chunkPage` 产出会合并写入 `data/chunks.jsonl`（见 `01` §6），并在此后的阶段 C 与 `embeddings.bin` 按行对齐。阶段 B 不写 `data/`、不调 embedding。
