# 02 开发工作计划（至 RAG 闭环）

依据 `01-设计文档.md`。实现采用 TDD（Vitest，先红后绿）。

---

## 1. 「RAG 结束」指哪一步

RAG（检索增强生成）在本项目中，指一条问题走完整条链路并给出带出处的回答。

**本计划的结束点：**

```text
维基 API → 清洗切片 → embedding → 三份知识文件
                │
                ▼
用户问题 → plus 改写 → 问题 embedding → 本地检索
       → qwen3-rerank → plus 根据切片作答（含 Wiki 链接）
```

同时满足：

1. 管理端「同步 Wiki」可全量或差量写入 `chunks.jsonl` / `embeddings.bin` / `pages.json`。
2. `POST /api/chat`（或等价接口）一次请求能完成：改写 → 向量检索 → rerank → 生成，响应中含回答正文与维基 URL。

**后补（本计划之后）：** 问答界面与流式输出；定时自动同步。

知识落盘（§1 上半段）只是 RAG 的「库」；没有检索和生成，RAG 尚未结束。问答页不在本计划内。

## 2. 阶段划分

### 阶段 A 脚手架

见 `03-阶段A-脚手架.md`。

- 初始化 Next.js（App Router）+ TypeScript。
- 接入 Vitest，可运行 `lib/**/*.test.ts`。
- 目录按 01：`lib/`、`tests/fixtures/wiki/`、`data/`（gitignore）、`app/admin/`。
- 环境变量骨架：`DASHSCOPE_API_KEY`、`ADMIN_TOKEN`、`DATA_DIR`、`WIKI_*`。

### 阶段 B 切片（TDD）

- 录制 fixture：NPC、作物、社区中心各至少一篇的 `extracts` / `parse`。
- 先写失败测试，再实现 `lib/chunk.ts`：infobox 独立成块、按 H2/H3 切、黄金 jsonl 通过。
- 核心页 fixture 切片测试全绿后，再扩大页面集合。

### 阶段 C 存储与 embedding（TDD）

- `lib/embed.ts`：可注入；契约 `dimensions === 1024`、单次最多 10 条。测试用假向量。
- `lib/store.ts`：jsonl 第 i 行与 bin 第 i 条对齐；原子写入（`.new` 再 rename）；失败时正式文件仍为上一份快照。

### 阶段 D 同步（TDD）

- `lib/wiki.ts`：可注入；测试用 fixture。
- `lib/sync.ts`：无快照则全量；有则按 `revid` 差量（改 / 增 / 删 / 重定向）；未变页 embedding 调用次数为 0。
- `/admin` + `POST/GET /api/admin/sync`：立即返回、锁、`sync-status.json` 轮询。
- 接入真实 Wiki API 与百炼 embedding，先少量页面人工确认，再全量同步一次。

### 阶段 E 检索与生成（TDD）

- 内存载入 bin + jsonl；问题 embedding 后余弦 / 点积取候选。
- MiniSearch：标题、物品名、NPC 名字面匹配，与向量结果合并后再 rerank。
- `qwen3-rerank`：对候选切片打分，取前若干条。
- `qwen-plus` 改写问句；`qwen-plus` 根据切片生成回答，prompt 含 URL。
- 测试（假切片、假模型）：prompt 含引用 URL；无命中时的约定回复。

### 阶段 F 问答接口与部署

- `POST /api/chat`：请求里带问题，跑通阶段 E，返回回答与引用（标题 + URL）。
- Docker：web 单容器，`data/` 挂 volume；同步成功后 reload 内存索引。

## 3. 完成标准

本计划完成当且仅当：

- `npx vitest` 全绿。
- 管理端可完成一次真实全量同步，三文件对齐且 `meta.json.count` 正确。
- 再点同步，未改动页不重新 embedding。
- 用至少 3 个问题（礼物、作物、地点/任务类）调用 `/api/chat`，响应含相关维基链接。
