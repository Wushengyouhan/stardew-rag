# 03 阶段 A：脚手架

依据 `01-设计文档.md`、`02-开发工作计划.md` 阶段 A。本阶段只搭可运行的工程骨架。

---

## 1. 范围

要做：Next.js 工程、Vitest、约定目录、环境变量示例文件。

后补：`/admin` 同步页与同步 API（阶段 D）；Docker（阶段 F）；问答界面与流式输出。

---

## 2. 脚手架

用 **create-next-app** 在仓库根目录初始化（保留已有 `docs/`、`.cursor/`）。

| 项 | 选择 |
|---|---|
| 框架 | Next.js，App Router |
| 语言 | TypeScript |
| 包管理器 | npm（`package-lock.json`） |
| 代码位置 | 仓库根目录下的 `app/`、`lib/` |
| 路径别名 | `@/` 指向仓库根（例如 `@/lib/chunk`） |
| 检查 | ESLint |

脚本：

- `npm run dev`：本地开发
- `npm test`：跑 Vitest

根路径 `/` 沿用脚手架默认页。

---

## 3. 目录

阶段 A 建好下列位置；`lib/` 下业务模块从阶段 B 起按 TDD 添加。

```text
app/                       # App Router
lib/                       # 业务代码与 *.test.ts
lib/smoke.test.ts          # 占位测试，保证 npm test 为绿
tests/fixtures/wiki/       # 阶段 B 放入 extracts / parse
data/                      # 本地知识目录，gitignore
.env.example               # 变量名清单，无密钥
.env.local                 # 本机密钥，不入库
```

`data/` 内知识文件不进 git。可用 `data/.gitkeep` 保留空目录。

---

## 4. 测试

- 框架：Vitest，匹配 `lib/**/*.test.ts`。
- 阶段 A：一条占位用例（例如断言 `true`），`npm test` 通过即可。
- 切片、存储、同步用例从阶段 B 起按 01 §11 编写。

---

## 5. 环境变量

仓库提交 `.env.example`，本机复制为 `.env.local` 后填写。

| 变量 | 用途 | example 中的值 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 百炼 API Key | 空 |
| `DASHSCOPE_BASE_URL` | 兼容模式基址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `ADMIN_TOKEN` | 同步接口鉴权 | 空 |
| `DATA_DIR` | 知识文件目录 | `data` |
| `WIKI_API_URL` | 维基 API | `https://zh.stardewvalleywiki.com/mediawiki/api.php` |
| `WIKI_USER_AGENT` | 采集标识 | `stardew-rag (dev)` |

阶段 A 不调用这些变量。`.gitignore` 包含 `.env.local` 与 `.env`。

---

## 6. 完成标准

- `npm run dev` 能打开默认首页。
- `npm test` 全绿。
- 目录与 `.env.example` 按上文就位。
